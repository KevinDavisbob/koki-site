前几天给一个微信群做了个 AI 助手：群里 @它一下，它就用 DeepSeek 生成回复自动发出去。功能听起来简单，但微信 4.x 几乎堵死了所有"正规"的自动化路线，最后走成了一条很有意思的野路子。这篇文章复盘一下完整思路和踩过的坑。

## 第一堵墙：没有接口

做微信机器人，网上流传的方案大多是 itchat / wechaty 这类**协议接口**。但有两个问题：

1. 非官方协议随时可能失效，微信改版就挂
2. 有封号风险

而走"官方"路线？微信根本没有面向个人的自动化 API。

那就只剩一条路：**模拟人怎么用微信**。人用眼睛看屏幕、用鼠标点击，那机器就截图当眼睛、模拟点击当手。

## 第二堵墙：UIA 树是空的

Windows 上做 UI 自动化的常规思路是 UIA（UI Automation）——像爬虫一样读窗口的元素树，找到"消息列表"控件再读它的文本。但微信 4.x 是 Qt 自绘界面，**UIA 树几乎为空**，读不到任何消息内容。

这条路堵死之后，方案就清晰了：**截图 + OCR**。

```python
# 核心循环：看 → 想 → 说
while True:
    screen = capture_window(hwnd)          # 看：截取微信窗口
    messages = ocr.extract_bubbles(screen) # 想：OCR 识别气泡文字
    new = [m for m in messages if m.side == "left" and m.id not in seen]
    for m in new:                          # 说：生成回复并发送
        reply = deepseek.chat(m.text)
        send_message(hwnd, reply)
    time.sleep(3)
```

几个关键设计：

- **左右气泡区分**：自己发的消息在右侧，别人的在左侧。OCR 时按气泡的 x 坐标分类，自己的消息直接忽略，否则机器人会跟自己无限对话。
- **去重**：每条消息记一个 id（文本 + 位置 + 时间），避免重复回复同一条。
- **分层**：感知（截图/OCR）、决策（生成回复）、执行（点击/输入）拆成独立模块，任何一个环节都能单独调试。

## 那些只能靠踩坑知道的细节

**滚轮事件只发给焦点窗口。** 想把消息列表往下滚，模拟 `mouse_event` 滚轮是不行的——微信窗口不在前台就收不到。解决办法是直接向微信的窗口句柄发消息：

```python
import ctypes
# WM_MOUSEWHEEL：绕开焦点限制，直发目标窗口
wParam = (120 << 16)  # +120 向上滚三格
ctypes.windll.user32.PostMessageW(hwnd, 0x020A, wParam, 0)
```

`PostMessage` 不等待窗口响应、也不需要焦点，正好绕开这个限制。

**点击会话后聊天区会白屏 2 秒。** 每次切换会话，聊天区会重新渲染约 2 秒，期间截图只能看到白屏。所以切换后不能立刻 OCR，得**轮询等待**：先等 2 秒，再验证标题栏文字是否已经是目标会话，确认渲染完成才继续。这类"不可靠的感知"必须配套验证，不然就会读到一堆空白。

**机器人运行期间，微信窗口必须可见、鼠标不能动。** 坐标点击没有"智能"，界面一移动就点到别处。这也决定了它只能在自己电脑上跑，是个"单机挂机"方案。

## 工程上的一点取舍

调试期最容易手滑把半成品回复发进群里，所以做了几个模式：

```bash
python bot.py            # 真实运行（会真的发送）
python bot.py --dry-run  # 只生成回复，打印在终端，不发送
python bot.py --shot     # 截一张图存下来，调试 OCR 用
python bot.py --dump     # 转储当前状态
```

`--dry-run` 是最有用的一个：**让副作用可控**。在真实环境里做自动化，先"只读"、再"只写日志"、最后才"真正执行"，这个原则值得记住。

## 这个方案到底算不算好？

实话实说：**脆弱**。

- 微信一改版（哪怕是聊天气泡换个圆角），OCR 模板和坐标全要重调
- 慢：截图 + OCR + 等渲染，一条回复从发出到响应要好几秒
- 丑：窗口必须可见，还不能用那台电脑干别的

但它有个最大的优点：**不碰协议、不碰账号安全边界**。所有操作都是"一个用户用自己的账号做自己能看到的事"，没有注入、没有伪造、没有封号风险——对一个练手项目来说，这比优雅重要得多。

## 收获与下一步

这个项目最大的收获不是那个 bot，而是：

1. **Windows 消息机制**：`PostMessage` vs `SendMessage`、焦点与消息路由，逆向和恶意软件分析的基础
2. **把不可靠的感知变成可靠的状态机**：截图会失败、OCR 会认错、渲染要等待——工程化就是给每个环节加验证
3. **副作用的控制**：dry-run 思维，任何自动化都要先能"预演"

下一步想做的：用视觉模型直接理解整张截图（省掉 OCR 的模板维护）、多群消息队列、断线重连。
